# v7s 지시 — 가이드 4~7단계 실기기 검증 (2026-11-10, Claude 작성)

**정본**: v7r 종결 + 인수인계. **CEO 승인(2026-11-10): AI 파싱 요청 3~5회 한도.**

## 목표
3/7(savedDetail)에서 이어서 4/7 음성 조회 → 5/7 변경 발화 → 6/7 수정 확인·저장 → 7/7 변경 완료 → 마무리(동기화 선택)까지 실기기 코치마크 증거 수집.

## v7s 실행 절차
1. 큐 lease(SM-S918N, versionCode 198 매칭, 회전값 기록).
2. refresh_token 갱신 1회(원자적 교체 절차) → 영수증 7키 → 5분 내 라운드 러너(start-bound-detail-round.ps1 계열) 실행. logcat -c 후 post-run 버퍼 덤프.
3. 라운드 진행(탭 총 15회 이내, min(30분, 세션 잔여기간)):
   - 안내 계속 1회 → 저장 일정 행 1회 탭 → 상세 진입(3/7 확인) → **준비·출발 안내 확인 버튼 1회 탭** → 4/7(쿼리 마이크 하이라이트) 확인.
   - 4/7에서 음성 입력: 기존 라운드 하니스의 입력 메커니즘(11-05 라운드 방식 — 시뮬레이션 전사 또는 실제 발화 중 기존 것) 사용. 문장: "내일 일정 보여줘" → 5/7 확인.
   - 5/7에서: "첫 번째 일정 오후 3시로 변경해줘" → 6/7(수정 확인 화면, 변경 시간 3시 강조) 확인.
   - 6/7에서 실제 저장 버튼 1회 탭 → 7/7(변경 완료, 같은 일정 시간이 3시로 바뀐 것 표시) 확인 → 확인 버튼 → 동기화 선택 화면 → 선택 → 마무리 코치마크 확인.
   - AI 파싱 요청은 위 발화 2건의 해석에 필요한 분만 허용(한도 5회 — 재시도 포함 총 5회 초과 금지). 각 호출 후 journal aiRequests 값 기록.
4. **각 단계마다 스크린샷+uiautomator dump**(07~13번 계속 번호), screen_evidence 절대경로 기록. 중단 시(안내가 잠시 멈췄어요·대기 문구) dump + run-as 진단 전문 수집 후 보고(탭 금지).
5. 종료 후 앱 files/ 진단 전문 수집(journal·anchor diagnostics·readback — 발췌 금지).
6. lease 반납, 회전값 0→0, 상태 JSON 저장. 잔여 파일 경로만 보고.

## 불변
refresh 1회·begin은 앱 자동. generate_link·verify·직접 begin/events 금지. 새 일정 생성 금지(변경 대상은 바인딩된 저장 일정만 — 변경 자체는 6→7단계 검증에 필요하므로 승인 범위). AI 파싱 5회 한도(CEO 승인 2026-11-10). monkey/kill-server/래퍼 우회/큐 state 편집 금지. 토큰 출력 금지. 완료 판정은 폰 화면 증거로만.
