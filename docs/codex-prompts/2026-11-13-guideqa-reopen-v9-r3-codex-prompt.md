# v9-r3 델타 지시 — 매직링크 발급·사용 정확 절차 + 튜토리얼 1~7 (2026-11-14, Claude 작성)

**정본**: v9-r2 델타. **서픽스 빌드 설치·프로덕션 무사 확인 = 좋음. 링크 3회 시도 실패의 원인은 알려진 함정이다 — v6 때 동일 사고가 있었다.**

## Claude 진단 (v6 선례)
- generate_link 응답은 **평탄화 스키마**다: `action_link`·`hashed_token`·`properties` 등이 **최상위**에 있다. `user.id` 같은 중첩 구조를 기대하면 "사용할 수 없음"으로 오인한다(v6 때 실제 발생, 기록된 함정).
- 또한 **링크는 수명이 짧다**(발급 후 수십 초~수분). 발급과 사용 사이에 지연이 있으면 만료 — 3회 연속 발급 후 늦게 사용하면 전부 만료된다.
- 따라서: **발급 → 수 초 내 즉시 deeplink 오픈**을 한 사이클로 묶는다. 3회 발급분은 자연 만료 — 추가 조치 불요.

## v9-r3 실행 절차
1. 큐 lease(SM-S918N, 회전값 기록). 서픽스 APK(com.fluxstudio.planflow.guideqa, v203) 설치 상태 확인.
2. **매직링크 사이클(최대 2회, 각 회 즉시 사용)**:
   a. admin generate_link 1회 호출(기존 v6/v7e 런북, email=QA 계정) → 응답 즉시 파일 저장.
   b. 응답에서 **최상위 `action_link` 필드**를 그대로 추출(중첩 구조 기대 금지, 재조립·수정 금지).
   c. **수 초 내** 기기 deeplink 오픈: `adb shell am start -a android.intent.action.VIEW -d "<action_link>" com.fluxstudio.planflow`.
   d. 앱에서 로그인 성공 확인(세션 확보, sub==QA UID 2cc42b8e-…). 성공 시 사이클 종료. 실패(만료·오류)면 기록 후 남은 1회로 반복 — 각 회는 발급 직후 즉시 사용.
   - 토큰·링크 값의 공용 출력 금지(기기 deeplink 용도만).
3. **튜토리얼 실행(실사용 UX 그대로)**: 앱 재시작 → 인트로 → **1/7 홈 마이크 코치마크**(스크린샷+dump) → 마이크 탭 → CEO 발화 "내일 오후 3시 서울역에서 회의"(화면이 연습 문구를 요구하면 그것 우선) → 확인 화면 → **2/7 저장**(중요→강한 알람→저장, 각 스크린샷) → 저장 → **3/7 savedDetail** → 준비·출발 안내 확인 탭 → **4/7** → CEO 발화 조회(생성 일정 날짜 맞춰 "내일/오늘 일정 보여줘") → **5/7**(첫 번째=새 일정) → CEO 발화 "첫 번째 일정 오후 5시로 변경해줘" → **6/7**(오후 5시 강조) → 실제 저장 탭 → **7/7**(실제 변경) → 확인 탭 → 동기화 선택 → 마무리 코치마크.
   - 각 단계 스크린샷+dump(번호 계속). AI 호출은 앱 자연 동작(≈3~4회 — 기존 승인 범위). 중단 화면 시 dump+logcat 수집 후 보고(탭 금지).
4. 성공 기준: **7/7 도달 + 마무리 코치마크 + 새 일정 실제 저장·변경 화면 증거**.
5. lease 반납, 회전값 0→0, 상태 JSON. 잔여 파일 경로만 보고. 배포는 별도 지시 대기.
