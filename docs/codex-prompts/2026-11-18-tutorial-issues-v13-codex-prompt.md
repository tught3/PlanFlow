## 실행 절차
1. **원인 특정 3건**: 각 이슈별로 코드 위치(파일:행) + 재현 절차 + 근본 원인을 보고 형식으로 정리.
2. **수정**:
   - 이슈 1: 완료 시점에 ConfirmScreen(2/7이 덧씌워질 화면)으로 **바로 이동**(중간 라우트 제거 또는 replace). 파싱 로딩이 필요하면 ConfirmScreen 내부 로딩 상태로 처리(별도 화면 노출 금지).
   - 이슈 2: 가이드 6/7(editPreview/updatedDetail 진행) 중 실제 저장이 가이드 상태 때문에 막히지 않아야 한다 — 가이드가 active·올바른 단계인데 막힌다면 가드 로직 버그(예: run=paused로 떨어진 것)를 수정. 단, 보안 가드(소유권·revision·중복 방지)는 약화 금지 — "가이드가 실제로 진행 중일 때는 저장이 되어야 한다"가 기준. 가이드가 paused로 내려가는 원인(lifecycle suspend 등)이 있으면 그것도 근본 수정.
   - 이슈 3: 동작이 정상이면 **가이드 문구/안내 개선**(예: "일정 탭에서 확인해 주세요" 명시) 또는 홈 탭 표시 보강 중 사용자 기대에 맞는 최소 수정. 버그가 아니면 코드 수정 없이 문서화만 해도 된다(보고에 명시).
3. **테스트**: 이슈 1 라우트 순서 검증 테스트, 이슈 2 가이드 진행 중 저장 성공 테스트 각 1건 + 기존 voice/가이드 스위트 통과 유지. 전체 스위트는 기준선 부분집합 확인.
4. **커밋·push**: 브랜치 fix/tutorial-ux-3issues-20261118 생성 → 커밋 → push.
5. **기기 확인**: guideqa 서픽스 빌드 재설치 → 튜토리얼 이어서: 1/7 음성 완료 → **중간 화면 없이** 2/7 → 저장 → 3/7 → 4/7 조회("내일 일정 보여 줘") → 5/7 → 변경 → 6/7 → **저장 성공** → 7/7 → 동기화 선택 → 마무리. 각 단계 스크린샷+dump.
6. 성공 기준: 이슈 1·2 해소 + 7/7 도달 + 일정 실제 변경 증거.
7. 보고: 결과 한 줄 / 3건 각각 원인·수정(또는 정상 판정) / 테스트 증거 / 기기 증거 경로 / 잔여 경로.
