# v17 지시 — 튜토리얼 UX 후속 3건(화면 전환 플래시 제거·안내 선표시·로딩 블러) (2026-11-22, Claude 작성)

**CEO 테스트 결과: 이전 3건 잘 해결됨. 남은 UX 3건은 전부 "사용자에게 보이는 것"이 핵심이다.**

## CEO 보고 3건
1. **3/7 전환 시 일정 탭이 1초간 보였다가 홈으로 옴**: 일정 탭을 사용자에게 보여주지 말 것. 일정 탭 확인이 꼭 필요하면 **로딩 중.. 블러 처리**(AI 일정 분배 때처럼)하고 백그라운드로 처리한 뒤 바로 홈으로. 사용자에게는 홈 화면만 보이게.
2. **일정(캘린더 항목) 클릭 → 일정이 먼저 보이고 안내가 늦게 뜸**: 사람들이 일정 확인으로 들어왔다가 버튼 누르려다 갑자기 안내가 떠서 깜짝 놀람. **안내(코치마크)가 먼저 떠야 한다** — 일정 화면 렌더와 안내 표시 순서를 뒤집거나, 안내 오버레이를 첫 프레임부터 표시.
3. **6/7 저장 중 "일정을 저장하고 있어요" 로딩**: 저장 진행 표시가 밝은 색이라 화면이 깜빡임 → **밝지 않은(어두운/블러) 표시**로 통일. 안내 박스 뜨기 전 화면 깜빡임 제거.

## 공통 설계 원칙 (이미 코드에 있는 것 재사용)
- AI 일정 분배 때 쓰는 로딩 블러 처리 패턴을 3/7 전환과 6/7 저장에 재사용.
- 안내 오버레이는 첫 프레임부터 표시(렌더 후 지연 부착 금지).
- 화면 전환 시 중간 화면(일정 탭) 노출 금지 — replace/직행.

## 실행 절차
1. **원인 특정 3건**:
   - 1번: savedDetail→홈 전환 과정에서 일정 탭이 잠깐 렌더되는 지점(route push 순서·캘린더 로딩 타이밍) 코드 확인.
   - 2번: 일정 상세/편집 화면 진입 시 안내 오버레이 부착 타이밍(첫 프레임 여부) 확인.
   - 3번: 6/7 저장 중 로딩 표시의 스타일(밝은 색)과 위치 확인.
2. **수정**:
   - 1번: 일정 탭 렌더를 스킵 — 전환 시 블러/로딩 오버레이를 먼저 띄우고(기존 AI 분배 로딩 패턴 재사용) 백그라운드에서 캘린더 데이터 확인 후 홈으로 직행. 일정 탭 화면 노출 없음.
   - 2번: 가이드 단계 화면 진입 시 안내 오버레이 첫 프레임부터 렌더(코치마크가 상태 변화를 기다리지 않고 즉시 표시).
   - 3번: 저장 중 표시를 어두운/블러 스타일로 통일(AI 분배 로딩과 같은 패턴).
3. **테스트**: ① 전환 중 일정 탭 미노출 검증 ② 화면 진입 시 안내 오버레이 첫 프레임 표시 검증 ③ 저장 로딩 스타일 검증 ④ 기존 guide 스위트 통과 유지.
4. **커밋·push→main 머지**(v9-r8 이후 절차) → guideqa 서픽스 재빌드·설치.
5. **자체 검증(Codex 완주)**: 튜토리얼 이어서 — 2/7 저장 → 3/7 전환 시 **일정 탭 미노출**(블러/로딩만) → 홈 탭 3/7 확인 → 일정 클릭 → **안내가 먼저 표시** → 4/7 조회 → 5/7 변경 → 6/7 저장 → **어두운 로딩 표시** → 저장 성공 → 7/7 → 동기화 → 마무리. 각 단계 스크린샷+dump.
