# v15-r4 델타 지시 — 설정의 "튜토리얼 다시하기"가 저장 게이트을 깨는지 검증·수정 (2026-11-19, Claude 작성)

**CEO 가설(유력): 첫 런 저장 성공 후, 설정에서 "튜토리얼 다시하기"를 하면 가이드 상태가 초기화되면서 두 번째 런 6/7 저장 게이트가 깨진다. 이 경로를 조사·수정한다.**

## 조사 대상
1. 설정 화면의 "튜토리얼 다시하기" 처리 위치(lib grep: 설정/튜토리얼 다시하기/재시작) → 무엇을 초기화하는지: ① guide_progress 키 삭제 ② 새 가이드 세션 생성(sessionId 교체) ③ provider invalidate/coordinator 재생성 ④ revision 리셋 여부.
2. 그 초기화가 6/7 저장 게이트(event_edit_screen entry/postDispatch)와 어떻게 충돌하는지: 초기화 후 sessionId/revision/step이 바뀌면 편집 화면이 들고 있는 캡처 snapshot과 불일치 → entry 가드 또는 postDispatch 가드에서 차단(토스트).
3. **재현 시퀀스(CEO 실측과 동일)**: 첫 런 6/7 저장 성공 → 설정에서 튜토리얼 다시하기 → 두 번째 런 6/7 저장 → 토스트 재현 여부 + 계측 로그(postDispatch의 snapshot.revision/confirmed.revision, sessionId 불일치 여부) 캡처.

## 판정·수정 규칙
- 재현되고 원인이 "초기화로 sessionId/revision/step이 바뀜"이면: 편집 화면의 저장 가드가 **초기화 후의 최신 가이드 상태**를 기준으로 동작하도록 수정(이미 provider 경유로 바꿨다면 남은 문제는 캡처 snapshot 재사용 — dispatch 직전 최신 상태 재구성으로 해소. v14-r2 규칙과 동일).
- 초기화 자체가 잘못(진행 중인 세션을 파괴, createdEventId 소실 등)이면 초기화 로직을 수정(완료되지 않은 세션은 폐기 후 새 시작 — 이건 허용된 동작이지만 편집 화면과 충돌 없게 순서·타이밍 정리).
- 동작이 정상이고 CEO 기대와 다른 UX면 안내 문구 개선으로 기록.

## 실행 절차
1. 설정 "튜토리얼 다시하기" 코드 위치·초기화 내용 조사(파일:행) → 보고.
2. 재현 시퀀스 실행 + 계측 로그 캡처(entry/postDispatch의 sessionId·revision 불일치 포함).
3. 원인 확정 → 위 규칙으로 수정(가드 약화 금지) → 테스트 1건 추가(초기화 후 두 번째 런 저장 성공).
4. 전체 타깃 테스트 통과 → 커밋·push(브랜치).
5. guideqa 서픽스 빌드 → install -r → **CEO 실측 시퀀스 재검증**: 첫 런 저장 성공 → 설정에서 다시하기 → 두 번째 런 6/7 저장 성공(토스트 부재) → 7/7까지 진행. 각 단계 스크린샷+dump.
6. 보고: 결과 한 줄 / 초기화 로직 위치·내용 / 원인 / 수정 diff / 테스트 증거 / 재검증 증거 경로 / 잔여 경로.
